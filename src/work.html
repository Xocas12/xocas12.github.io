Land intelligence platform

in production private client work

Land acquisition platform for Samford Group, where I'm the only engineer. It screens US parcels for development and runs the team's acquisition, outreach and finance workflows. Roughly 200k lines of product code, with more than that in tests.

  • 24 source adapters (FEMA flood, USFWS wetlands, USGS elevation, Census, OSM, listings and others) feed per-parcel floodplain share, slope, road frontage and lot yield.
  • Adding a county is one command: ingest the parcel dump, derive the FIPS code, run the full pipeline. There is no per-county code. A weekly job re-checks every county and rolls back any refresh that would drop data.
  • An MCP connector with 67 tools and OAuth sign-in lets analysts query and update the app from Claude. Write tools are off by default.
  • Issues close against tests named after them: about 7,000 JS test cases, 1,325 pytest tests and 246 browser checks. A script swaps the pre-fix code back in and requires those tests to fail.
  • Also a deck generator that computes yield two ways and flags disagreement, a vector tile server, invoice extraction from email, a cash-flow plan, and outreach with do-not-call suppression and database-level send dedup.

Vixía · OSINT event map

live

Watches Telegram channels and eight other open sources, merges corroborating reports into geolocated events, and plots them on a public map. Seven Python services around PostGIS, coordinated through a Postgres job queue.

  • Every event links back through its sources to an append-only raw archive. Corrections are new rows, and derived tables rebuild from raw data and code.
  • Confidence is weighted by source independence, so fifty reposts of one claim count once. Corroboration can also come from other sensors: seismic stations, satellite fire detection, outage data.
  • Ingest uses deterministic NLP (GLiNER, fastText, gazetteer geocoding). An LLM only sees the ambiguous cases.
  • An investigation agent works through the same CLI people use. A CI test parses its skill files and fails if one uses a verb outside the documented contract.
  • Three small agents handle routine dev work. One proposes tasks from the roadmap, one turns approved issues into PRs through a signed webhook, and one screenshots the live map every eight hours and files a bug if it didn't render. I review and merge every PR myself.

OGE · strategy simulation platform (CMU)

research · large team

Multiplayer wargaming platform CMU is building for classroom use from fall 2026. I worked on the multi-agent backend and the facilitator frontend.

  • The engine combines fuzzy cognitive maps, a stock-and-flow model and an MDP. The LLM's only job inside it is translating a player's free-text decision into a change in world state. Scenario generation and adjudication are kept separate so one model never both sets and scores a problem.
  • Matrix-game adjudication for White Cell injects and rulings, with a human review gate.
  • Engine parameters were fit with a 150-job sweep on CMU's Wright HPC cluster instead of being hand-tuned.
  • A prompt-injection filter in front of the models, and a scenario-agnostic after-action review template.
  • Frontend: the facilitator console, with per-advisor chat monitoring, per-player token budgets an instructor can change mid-game, and advisors built from RAG document sets and remote MCP servers.

ModMatch · compatibility-checked watch builds

private beta

PCPartPicker for Seiko mods. A six-step configurator checks fit as you go. Dimensions are stored as tolerance ranges, so a pairing can pass, fail, or pass marginally with a warning, and curators can override the rules with known-good or known-bad pairings. Prices from four Shopify stores and the AliExpress API are normalized into one catalog every six hours, and a comparison view finds the cheapest vendor mix for a build. Builds share by link without an account. Affiliate tracking covers click logging with salted IP hashes through last-click attribution of commission CSVs.

Most of the work was cleaning: missing values, duplicates and schema drift across decades of filings. product-idea-coach

open source · mit

A Claude Code skill that takes a rough product idea to a specified concept, following the product-management method taught at CMU. It has two modes: a coach that stops at three decision points for the user, and a one-shot generator that lists the assumptions it made. The model checks its draft against a rubric before showing it, and the core numbers have to stay consistent from problem sizing through pricing to market size.
